## Audit objective

Decide whether this resolves the previously identified persistence and missing-action failures without changing the product thesis or introducing data-loss regressions. Read AGENTS.md and relevant product docs first. MVP/SCREENS are currently under docs/, although AGENTS.md references copies under docs/product/ that do not exist.

## Scope

- One versioned snapshot of submitted profile, inventory, and current action (including dueAt and status).
- Hydration before screen mounting; restart routing based on saved progress.
- Ordered writes and explicit load/save failure handling.
- Atomic new-inventory reset preserving profile.
- Missing-action redirects for next-action, smaller, and commitment.
- No sober date, analytics, backend, auth, live AI, redesign, or unrelated copy changes.

## Verification

Use Node 22. Install from the lockfile with `npm ci`, then run:

```
npm test
npm run typecheck
EXPO_NO_TELEMETRY=1 npm run lint
EXPO_NO_TELEMETRY=1 npx expo export --platform web
```

Executed results and limitations are in docs/STATUS.md. Independently inspect the provider lifecycle, not only the pure helper tests. In particular:

1. Delay hydration: verify no empty/default snapshot overwrites saved state and screen-local initial state uses restored values.
2. Submit partial onboarding/inventory; restart from the root and verify progress remains accessible.
3. Choose an action, make it smaller, commit, restart, revisit, complete, and restart again. Verify title/detail/timing/status.
4. Start a new inventory and restart: old action/inventory must stay cleared, profile must remain.
5. Test missing data, invalid JSON, invalid field types, unsupported snapshot version, rejected reads, failed writes, and retry. Existing invalid data must remain untouched.
6. Open next-action, smaller, and commitment with no current action; verify usable action selection rather than blank/dead-end screens.
7. Review limitations: unencrypted local sensitive data, no automatic corruption reset, no persisted unsubmitted edits, async writes with no force-kill guarantee, no multi-tab synchronization.

Native-device validation has not been executed. Do not infer native behavior from the web export or unit tests.
